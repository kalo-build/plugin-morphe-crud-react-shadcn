# data-testid naming convention

Generated components emit `data-testid` attributes so Playwright (or other UI test runners) can target elements without relying on CSS or text. This convention is shared with **plugin-uicheck-playwright**: when you author `.up` (UI Pages) specs, use these same identifiers as element `key` values so generated Playwright tests match the generated React output.

## Table component

| Element | data-testid |
|--------|-------------|
| `<table>` | `{collection}-table` (e.g. `customers-table`, `projects-table`) |
| each `<tr>` in body | `{kebab}-row` (e.g. `customer-row`, `project-row`) |

`{collection}` is the plural kebab model name; `{kebab}` is the singular kebab model name.

## Form component

| Element | data-testid |
|--------|-------------|
| `<form>` | `{kebab}-form` (e.g. `customer-form`) |
| each `<input type="text|number|...">` | `{kebab}-{field-kebab}-input` (e.g. `customer-name-input`, `project-organization-id-input`) |
| each `<input type="checkbox">` | `{kebab}-{field-kebab}-checkbox` (e.g. `project-private-checkbox`) |
| submit `<button>` | `submit-button` |

## Detail component

| Element | data-testid |
|--------|-------------|
| `<dl>` | `{kebab}-detail` (e.g. `customer-detail`) |
| each `<dd>` | `{kebab}-{field-kebab}` (e.g. `customer-name`, `customer-email`) |

## Authoring .up specs

In your UI Pages (`.up`) specs, set each element’s `key` to the corresponding value from the tables above. For example, for a Customer model:

- List page table: `key: customers-table`
- Form: `key: customer-form`; fields `customer-name-input`, `customer-email-input`, etc.; submit `submit-button`
- Detail: `key: customer-detail`; fields `customer-name`, `customer-email`, etc.

Then `plugin-uicheck-playwright` will generate `page.getByTestId('customers-table')` and similar, and the components generated by this plugin will render matching `data-testid` attributes.
